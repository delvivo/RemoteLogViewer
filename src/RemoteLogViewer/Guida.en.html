Remote Log Viewer

User guide · version %VERSION%

Introduction

Remote Log Viewer follows log files on Windows network shares (SMB), such as \\server\E$, in real time. It replaces the manual sequence:

New-SmbMapping -RemotePath "\\server\E$" -UserName "user" -Password "pwd"
Get-Content -Tail 1000 -Wait "\\server\E$\logs\app.log"

The app connects to the share without assigning a drive letter, reads the last lines of the file and shows new ones as they are written (it checks every half second). It handles file rotation, disconnections and files that do not exist yet on its own.

Sessions

A session is a saved configuration: where the file is and how to access it. Sessions appear in the Saved sessions panel on the left.

FieldMeaning
NameName shown in the list and in the tab title.
ShareIn the form \\server\share, for example \\nts11050\E$.
CredentialA shared credential, or none: in that case the User and Password below are used.
User / PasswordDOMAIN\user. If you leave the user empty, the current Windows user is used. When you edit a session, an empty password stays the same as before.
FileThe path relative to the share (logs\app.log) or the full UNC path, which must be inside the share. It can contain a variable date.
Initial linesHow many lines to read from the end of the file when opening (0 to 100,000). It is also the number of lines loaded each time with ▲ Older.
Encodingauto (UTF-8), UTF-16 or Windows-1252. If the file starts with a BOM, the encoding given by the BOM always wins.

Test connection tries to reach the share and the file without saving anything.

The buttons under the list are: Start, New, Edit (F2), Duplicate, Delete (Del) and Collection. To start a session you can also double-click it or press Enter.

Passwords are encrypted with DPAPI: only your Windows user, on this PC, can decrypt them. The sessions file is %APPDATA%\RemoteLogViewer\sessions.json.

Credentials

The Credentials… button in the top bar manages user names and passwords shared by several sessions (name, user, password). In a session, pick the credential in the Credential field. When the password changes, you update it once in the credential.

  • Sessions that are already open keep using the previous password until they are reopened.
  • If you delete a credential, the sessions that used it go back to their own user and password.
  • Credentials are never exported.

Collections

Collections are folders, also nested (for example PROD › API), used to organize sessions.

  • Collection creates a collection inside the selected one.
  • Right-clicking a collection offers: new session, new subcollection, rename, duplicate, move, export, import and delete. Right-clicking empty space offers the root actions.
  • You can drag sessions and collections onto another collection, or onto empty space to move them to the root.
  • Duplicate on a collection copies all its content, passwords included, as Name (copy).
  • Before deleting a collection with content, the app asks for confirmation and tells you how many sessions will be deleted.

Export and import

Right-click a collection and choose Export…; right-click empty space and choose Export all…. A .rlv.json file is created, to share with colleagues.

  • Passwords are not exported. After the import they must be entered again with Edit.
  • Import always adds new copies and never overwrites anything. If a name is already taken it becomes Name (2).
  • An imported session stays linked to its credential only if that credential already exists on this PC.

Date in the path

Many logs have a different folder or file for each day. In the File field write {date:format} in place of the date, using the .NET date format:

DOB\DOB_SDL\log\standard_logs\{date:yyyy_MM_dd}\log.log
logs\app_{date:yyyy-MM-dd}.log
  • When you start the session, the app asks for the date on a calendar (it proposes today) and shows a preview of the path.
  • The calendar checks which days of the displayed month have a log file: crossed-out days have no file and cannot be picked. Today is always selectable: if the file is not there yet, the session waits for it. If the share cannot be reached, the reason appears under the calendar and all days stay selectable.
  • If you picked today, at midnight the session switches to the new day's file by itself and shows the line — new day: … —. If you picked a past date, the session stays on that date.
  • The format may contain only day, month and year (no hours or minutes). A date is not allowed in the share.
  • If only the old logs have the date and the current file does not (e.g. today app.log, yesterday app.2026-09-29.log), put the separator inside the format, quoted, and tick Today's file has no date: 
    logs\app{date:'.'yyyy-MM-dd}.log
    For today logs\app.log is opened, for other dates the file with the date. At midnight the session stays on app.log: when the server renames it, the app detects it and restarts from the beginning of the new file.

Local files

To read a file on your PC (or on a drive Windows can already reach) without creating a session: Open file… or Ctrl+O opens the file dialog (several files at once are fine; Log and text and All files filters), or drag one or more files from Explorer onto the window.

  • Each file opens in a tab named after the file (the full path is in the tooltip; if two files have the same name the title becomes folder\name). A file that is already open is not duplicated: its tab is selected.
  • No credentials, no date and no network connection managed by the app: the file is read with your Windows user's permissions. For shares that need a user and password use a session.
  • The last 1000 lines are read, then the file is followed. ▲ Older loads more lines. Filters, search, advanced search, Save, error alerts and Side by side work as for remote sessions.
  • If the file is deleted the tab goes to Waiting for the file… and resumes when it comes back; if it is truncated or rotated, reading restarts from the beginning.
  • It is not added to the saved sessions list nor to exports. On close it is remembered and reopened at startup if it still exists (otherwise it is silently skipped).
  • Folders and non-file items that are dragged in are ignored; a file that cannot be opened (missing, no permission) gives a message and no tab.

Tabs and Side by side

Each session you start opens in a tab. The tab title shows a status dot, the session name (plus the date, if the path contains one), the error badge if any, and the ✕ button. To close a tab you can also middle-click its title.

  • To reorder tabs, drag a title onto another tab.
  • Side by side (top bar) shows all open sessions together, in a grid, in the same order as the tabs.

Reopening at startup

When you close the app, the open tabs, their order, the selected tab and the Side by side mode are remembered. On the next start everything is restored without questions.

  • A dated session that was following today reopens on the current date. A session opened on a fixed date reopens on the same date.
  • Sessions deleted in the meantime are ignored.
  • If a session cannot connect, its tab shows the error and the others open normally.

Error alerts

  • When an ERROR line arrives in a tab you are not looking at, a red badge with the number of errors appears on its title, for example 3. The badge disappears when you select the tab.
  • If the app is not in the foreground, its button in the Windows taskbar flashes until you go back to the app.
  • An error followed by its stack trace counts as one error.
  • Lines read when the session opens and those loaded with ▲ Older do not raise alerts. In Side by side mode no badge appears, because all sessions are already visible.

Filters, context and search

Filter

Shows only the lines containing the text, ignoring case. If you turn on Regex, the text is read as a .NET regular expression; an invalid regex turns the border red. The level checkboxes apply together with the filter. Service lines are always visible.

Context

In the Context box you set how many lines to show before and after each line matching the filter (0 to 50), like grep -C. Context lines appear dimmed. Between groups, if they are not contiguous, a -- separator appears. With Follow on, the lines following a match appear as they arrive. Without a filter, context has no effect.

Search

Ctrl+F moves the cursor to the search box. Matching lines are highlighted in yellow; F3 and Shift+F3 jump to the next or previous result. Unlike the filter, search does not hide any line.

Advanced search across sessions

The Search… button or Ctrl+Shift+F opens a window that searches the lines already read in all open sessions, even if their tab is not visible and regardless of each tab's own filters. The window stays open while you use the tabs (also in Side by side).

  • Text (Enter to search), with optional Regex; Match case and Whole word are off by default.
  • Levels: only the ticked ERROR/WARN/INFO/DEBUG; the lines of a stack trace have the level of the line that opens it. With a partial filter, lines without a level are excluded.
  • From / To: date and time range (bounds included, both optional; a date alone means from the start or until the end of that day; a time alone is not allowed). The timestamp is read at the start of the line (2026-10-01 12:34:56,789, 01/10/2026 12:34:56 or just 12:34:56: then the date is the session's). Lines without a timestamp, like a stack trace, inherit the one of the previous line of the same session.
  • With empty text and at least one filter on, all the lines that satisfy it are listed.
  • Results are grouped by tab (Name · N), one row per match, highlighted. There are at most 10,000: beyond that the search stops and tells you. They are a snapshot: press Search again to refresh, Cancel stops a long search.
  • Double-click (or Enter) on a result selects the tab and scrolls the line into view. If the tab's filters hide it, they are cleared and the Filters cleared notice appears; if the line is no longer in the buffer, you are told.
  • Export… saves the shown results to a UTF-8 file, one # Name (N) block per session.

Older lines

When opening, only the last Initial lines of the file are read. ▲ Older loads another block of the same size (1000 lines if Initial lines is 0) and puts it above the lines already present. Reading new lines continues and the view does not jump.

  • The button is disabled when the start of the file is already loaded, when the session is not active, and after a file rotation (the new file is already read from the start).
  • If the block would exceed the 100,000-line limit, only as many lines as fit are loaded and the app tells you.

Saving and copying

  • Ctrl+S or Save… save exactly the visible lines to a UTF-8 file, with filters and context applied (separators become -- lines). The suggested name is <session>_<yyyyMMdd_HHmmss>.log.
  • Ctrl+C copies the selected lines. Shift and Ctrl+click are for multiple selection.

Session states

StateMeaning
Connecting…Connecting to the share.
ActiveThe file is being followed.
Waiting for the file…The file does not exist (yet): it is checked again every 2 seconds.
Reconnecting…The connection dropped after having worked: retry every 5 seconds, then reading resumes from where it stopped.
ErrorThe first connection failed (wrong credentials or path). There are no automatic retries: fix the session and press Start.
StoppedStopped with Stop.

Service lines appear in the view, such as — file truncated or rotated: reading from the start —, — disconnected — and — reconnected —.

Language

The interface and this guide are available in Italian and English. Choose the language with the Language selector in the top bar: the choice is saved (file %APPDATA%\RemoteLogViewer\lang.txt) and the change is immediate, no restart needed (a guide already open in the browser keeps the previous language: reopen it with F1). On first run the Windows language is used (Italian, otherwise English).

Troubleshooting

"Different credentials" error (1219)

Windows allows only one identity per server. If a connection to the same server with another user already exists (for example a mapped drive), close it with net use \\server\share /delete, or use the same credentials.

Password required after an import or on another PC

Passwords are not exported, and encrypted ones only work for your Windows user on this PC. Enter them again with Edit or in Credentials….

An existing mapping is not removed

This is intentional: the app only closes the connections it opened itself.

The guide does not open

The guide is written to %TEMP%\RemoteLogViewer\guide.en.html and opened with the default browser. If opening fails, the app shows the file path: you can open it by hand.
