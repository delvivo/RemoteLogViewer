Remote Log Viewer

Guida utente · versione %VERSION%

Introduzione

Remote Log Viewer segue in tempo reale i file di log presenti su share di rete Windows (SMB), come \\server\E$. Sostituisce la sequenza manuale:

New-SmbMapping -RemotePath "\\server\E$" -UserName "user" -Password "pwd"
Get-Content -Tail 1000 -Wait "\\server\E$\logs\app.log"

L'app si connette alla share senza assegnare una lettera di unità, legge le ultime righe del file e mostra le nuove man mano che vengono scritte (controllo ogni mezzo secondo). Gestisce da sola la rotazione dei file, le disconnessioni e i file che non esistono ancora.

Sessioni

Una sessione è una configurazione salvata: dove si trova il file e come accedervi. Le sessioni compaiono nel pannello Sessioni salvate a sinistra.

CampoSignificato
NomeNome mostrato nell'elenco e nel titolo della scheda.
ShareNel formato \\server\share, per esempio \\nts11050\E$.
CredenzialeUna credenziale condivisa, oppure nessuna: in quel caso si usano Utente e Password qui sotto.
Utente / PasswordDOMINIO\utente. Se lasci l'utente vuoto si usa l'utente Windows corrente. Quando modifichi una sessione, una password lasciata vuota resta quella di prima.
FileIl percorso relativo alla share (logs\app.log) oppure il percorso UNC completo, che deve trovarsi dentro la share. Può contenere una data variabile.
Righe inizialiQuante righe leggere dalla fine del file all'apertura (da 0 a 100.000). È anche il numero di righe caricate ogni volta con ▲ Precedenti.
Encodingauto (UTF-8), UTF-16 o Windows-1252. Se il file inizia con un BOM, vale sempre la codifica indicata dal BOM.

Test connessione prova ad accedere alla share e al file senza salvare nulla.

I pulsanti sotto l'elenco sono: Avvia, Nuova, Modifica (F2), Duplica, Elimina (Canc) e Collezione. Per avviare una sessione puoi anche fare doppio click o premere Invio.

Le password sono cifrate con DPAPI: solo il tuo utente Windows, su questo PC, può decifrarle. Il file delle sessioni è %APPDATA%\RemoteLogViewer\sessions.json.

Credenziali

Il pulsante Credenziali… nella barra in alto gestisce utente e password condivisi tra più sessioni (nome, utente, password). Nella sessione scegli la credenziale nel campo Credenziale. Quando la password cambia, la aggiorni una sola volta nella credenziale.

  • Le sessioni già aperte continuano a usare la password precedente fino a quando non vengono riaperte.
  • Se elimini una credenziale, le sessioni che la usavano tornano al proprio utente e alla propria password.
  • Le credenziali non vengono mai esportate.

Collezioni

Le collezioni sono cartelle, anche annidate (per esempio PROD › API), in cui organizzare le sessioni.

  • Collezione crea una collezione dentro quella selezionata.
  • Il tasto destro su una collezione offre: nuova sessione, nuova sottocollezione, rinomina, duplica, sposta, esporta, importa ed elimina. Il tasto destro su uno spazio vuoto offre le azioni sulla radice.
  • Puoi trascinare sessioni e collezioni su un'altra collezione, oppure su uno spazio vuoto per portarle alla radice.
  • Duplica su una collezione copia tutto il contenuto, password comprese, come Nome (copia).
  • Prima di eliminare una collezione con contenuto, l'app chiede conferma e indica quante sessioni verranno eliminate.

Esporta e importa

Con il tasto destro su una collezione scegli Esporta…; con il tasto destro su uno spazio vuoto scegli Esporta tutto…. Viene creato un file .rlv.json da condividere con i colleghi.

  • Le password non vengono esportate. Dopo l'import vanno reinserite con Modifica.
  • L'import aggiunge sempre copie nuove e non sovrascrive nulla. Se un nome è già in uso diventa Nome (2).
  • Una sessione importata resta collegata alla sua credenziale solo se quella credenziale esiste già su questo PC.

Data nel percorso

Molti log hanno una cartella o un file diverso per ogni giorno. Nel campo File scrivi {date:formato} al posto della data, usando il formato data di .NET:

DOB\DOB_SDL\log\standard_logs\{date:yyyy_MM_dd}\log.log
logs\app_{date:yyyy-MM-dd}.log
  • Quando avvii la sessione, l'app chiede la data su un calendario (propone oggi) e mostra un'anteprima del percorso.
  • Il calendario verifica quali giorni del mese visualizzato hanno il file di log: i giorni barrati non hanno il file e non si possono scegliere. Oggi resta sempre selezionabile: se il file non c'è ancora, la sessione resta in attesa. Se la share non è raggiungibile, sotto il calendario compare il motivo e tutti i giorni restano selezionabili.
  • Se hai scelto oggi, a mezzanotte la sessione passa da sola al file del nuovo giorno e mostra la riga — nuovo giorno: … —. Se hai scelto una data passata, la sessione resta su quella data.
  • Il formato può contenere solo giorno, mese e anno (niente ore o minuti). La data non è ammessa nella share.
  • Se la data c'è solo nei log vecchi e il file corrente no (es. oggi app.log, ieri app.2026-09-29.log), metti il separatore dentro il formato tra apici e spunta Il file di oggi non ha la data: 
    logs\app{date:'.'yyyy-MM-dd}.log
    Per oggi si apre logs\app.log, per le altre date il file con la data. A mezzanotte la sessione resta su app.log: quando il server lo rinomina, l'app lo rileva e riparte dall'inizio del nuovo file.

Schede e Affianca

Ogni sessione avviata si apre in una scheda. Il titolo della scheda mostra un pallino di stato, il nome della sessione (più la data, se il percorso ne contiene una), l'eventuale badge degli errori e il pulsante ✕. Per chiudere una scheda puoi anche fare click con il tasto centrale sul titolo.

  • Per riordinare le schede, trascina il titolo su un'altra scheda.
  • Affianca (barra in alto) mostra tutte le sessioni aperte insieme, in una griglia, nello stesso ordine delle schede.

Riapertura all'avvio

Quando chiudi l'app, vengono memorizzate le schede aperte, il loro ordine, la scheda selezionata e la modalità Affianca. Alla riapertura tutto viene ripristinato senza domande.

  • Una sessione con data che seguiva oggi si riapre sulla data del giorno corrente. Una sessione aperta su una data fissa si riapre sulla stessa data.
  • Le sessioni eliminate nel frattempo vengono ignorate.
  • Se una sessione non riesce a connettersi, la sua scheda mostra l'errore e le altre si aprono normalmente.

Avvisi di errore

  • Quando arriva una riga ERROR in una scheda che non stai guardando, sul suo titolo compare un badge rosso con il numero di errori, per esempio 3. Il badge sparisce quando selezioni la scheda.
  • Se l'app non è in primo piano, il suo pulsante nella barra delle applicazioni di Windows lampeggia finché non torni sull'app.
  • Un errore seguito dal suo stack trace conta come un solo errore.
  • Le righe lette all'apertura della sessione e quelle caricate con ▲ Precedenti non generano avvisi. In modalità Affianca non compare nessun badge, perché tutte le sessioni sono già visibili.

La vista tiene al massimo 100.000 righe. Oltre quel limite vengono scartate le più vecchie.

Filtri, contesto e ricerca

Filtro

Mostra solo le righe che contengono il testo, senza distinguere maiuscole e minuscole. Se attivi Regex, il testo viene letto come espressione regolare .NET; una regex non valida colora il bordo di rosso. Le caselle dei livelli si applicano insieme al filtro. Le righe di servizio restano sempre visibili.

Contesto

Nella casella Contesto indichi quante righe mostrare prima e dopo ogni riga che corrisponde al filtro (da 0 a 50), come grep -C. Le righe di contesto appaiono attenuate. Tra un gruppo e l'altro, se non sono contigui, compare un separatore --. Con Follow attivo, le righe successive a un risultato compaiono man mano che arrivano. Senza filtro, il contesto non ha effetto.

Ricerca

Ctrl+F porta il cursore nella casella di ricerca. Le righe trovate vengono evidenziate in giallo; con F3 e Shift+F3 passi al risultato successivo o precedente. A differenza del filtro, la ricerca non nasconde nessuna riga.

Ricerca avanzata tra le sessioni

Il pulsante Cerca… o Ctrl+Maiusc+F apre una finestra che cerca nelle righe già lette di tutte le sessioni aperte, anche se la scheda non è visibile e a prescindere dai filtri della singola scheda. La finestra resta aperta mentre usi le schede (anche in Affianca).

  • Testo (Invio per cercare), con Regex opzionale; Maiuscole/minuscole e Parola intera sono disattivate di default.
  • Livelli: solo ERROR/WARN/INFO/DEBUG selezionati; le righe di uno stack trace hanno il livello della riga che lo apre. Con un filtro parziale le righe senza livello sono escluse.
  • Da / A: intervallo di data e ora (estremi inclusi, entrambi facoltativi; la sola data vale dall'inizio o fino alla fine del giorno; l'ora da sola non è ammessa). Il timestamp è letto a inizio riga (2026-10-01 12:34:56,789, 01/10/2026 12:34:56 o solo 12:34:56: in quel caso la data è quella della sessione). Le righe senza timestamp, come lo stack trace, ereditano quello della riga precedente della stessa sessione.
  • Con il testo vuoto e almeno un filtro attivo vengono elencate tutte le righe che lo soddisfano.
  • I risultati sono raggruppati per scheda (Nome · N), una riga per ogni corrispondenza, evidenziata. Sono al massimo 10.000: oltre, la ricerca si ferma e te lo segnala. Sono un’istantanea: premi di nuovo Cerca per aggiornarli, Annulla ferma una ricerca lunga.
  • Doppio click (o Invio) su un risultato seleziona la scheda e porta la riga in vista. Se i filtri della scheda la nascondono vengono azzerati e compare l’avviso Filtri rimossi; se la riga non è più nel buffer, viene detto.
  • Esporta… salva i risultati mostrati in un file UTF-8, un blocco # Nome (N) per sessione.

Righe precedenti

All'apertura vengono lette solo le ultime Righe iniziali del file. ▲ Precedenti carica un altro blocco della stessa dimensione (1000 righe se Righe iniziali è 0) e lo mette sopra le righe già presenti. La lettura delle nuove righe continua e la vista non salta.

  • Il pulsante è disabilitato quando l'inizio del file è già caricato, quando la sessione non è attiva, e dopo una rotazione del file (il nuovo file viene letto già dall'inizio).
  • Se il blocco supererebbe il limite di 100.000 righe, ne vengono caricate solo quante ci stanno e l'app te lo segnala.

Salvare e copiare

  • Ctrl+S o Salva… salvano in un file UTF-8 esattamente le righe visibili, con i filtri e il contesto applicati (i separatori diventano righe --). Il nome proposto è <sessione>_<aaaaMMgg_HHmmss>.log.
  • Ctrl+C copia le righe selezionate. Shift e Ctrl+click servono per la selezione multipla.

Stati della sessione

StatoSignificato
Connessione…Connessione alla share in corso.
AttivaIl file viene seguito.
In attesa del file…Il file non esiste (ancora): viene ricontrollato ogni 2 secondi.
Riconnessione…La connessione si è interrotta dopo aver funzionato: nuovo tentativo ogni 5 secondi, poi la lettura riprende dal punto in cui si era fermata.

Nella vista compaiono righe di servizio come — file troncato o ruotato: lettura dall'inizio —, — disconnesso — e — riconnesso —.

Lingua

L'interfaccia e questa guida sono disponibili in italiano e in inglese. Scegli la lingua con il selettore Lingua nella barra in alto: la scelta viene salvata (file %APPDATA%\RemoteLogViewer\lang.txt) e il cambio è immediato, senza riavviare l'app (una guida già aperta nel browser resta nella lingua precedente: riaprila con F1). Alla prima esecuzione si usa la lingua di Windows (italiano, altrimenti inglese).

Problemi comuni

Errore "credenziali diverse" (1219)

Windows ammette una sola identità per server. Se esiste già una connessione allo stesso server con un altro utente (per esempio un'unità mappata), chiudila con net use \\server\share /delete, oppure usa le stesse credenziali.

Password richiesta dopo un import o su un altro PC

Le password non vengono esportate e quelle cifrate funzionano solo per il tuo utente Windows su questo PC. Reinseriscile con Modifica o in Credenziali….

Una mappatura esistente non viene rimossa

È voluto: l'app chiude solo le connessioni che ha aperto lei.

La guida non si apre

La guida viene scritta in %TEMP%\RemoteLogViewer\guide.it.html e aperta con il browser predefinito. Se l'apertura non riesce, l'app mostra il percorso del file: puoi aprirlo a mano.
